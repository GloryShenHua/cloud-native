# 后端实验报告素材

## 系统实现

后端使用 Java 21、Spring Boot、Spring JDBC、PostgreSQL 和 Flyway。Controller 负责 HTTP 路由和请求校验，Service 负责业务规则和事务，Repository 通过参数化 SQL 操作数据库。数据库连接信息由环境变量注入，HTTP 接口统一使用 JSON。

## 功能与接口

实现场地列表、详情和创建；预约创建、列表、详情和取消。所有实际路径、字段及错误格式见 README 第 3 节。预约取消使用逻辑取消，状态由 ACTIVE 改为 CANCELLED，历史记录保留。DELETE 和显式 cancel 接口行为一致。

## 数据库设计

venues 表以 id 为主键，保存名称、位置、容量、每日开放/关闭时间和状态。reservations 表以 id 为主键，通过 venue_id 外键关联场地，保存预约人、日期、开始/结束时间、用途和状态。数据库检查约束限制容量、时间先后和枚举状态；有效预约部分索引支持冲突查询。

Flyway 在应用启动时依次执行版本化迁移，首次建表并插入演示场地；后续启动根据版本历史跳过已应用脚本。PostgreSQL 数据目录挂载到命名 Volume，容器删除后数据仍可保留。

## 冲突控制

预约区间采用左闭右开语义。只有同一场地、同一日期的 ACTIVE 预约参与冲突判断，条件为已有开始时间早于新结束时间且已有结束时间晚于新开始时间。相邻时段允许预约，取消后可以重新预约。

创建预约使用 READ COMMITTED 事务并锁定场地行，保证“读取冲突与插入”在相同场地的并发请求之间串行执行。取消同样锁定场地行。锁由 PostgreSQL 管理，能够覆盖多个 API 进程，而不依赖 JVM 内存锁。

## Dockerfile 说明

构建阶段使用 Maven 和 JDK 21 生成可执行 JAR；最终阶段只保留 JRE、JAR 和健康检查工具，以非 root 用户运行。ENTRYPOINT 以前台 Java 进程启动应用，容器监听 8080。构建上下文通过 .dockerignore 排除 .env、本地 target、IDE 文件等无关内容。数据库账号密码只在运行时注入。
